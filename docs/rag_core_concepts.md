# RAG核心概念复习

## 完整流程

```text
文档读取 → 分块 → Embedding → 向量库
用户问题 → 查询改写 → 混合召回 → RRF → Reranker
→ 父块取回 → 阈值过滤 → 证据编号 → 生成 → 引用校验
```

## 为什么分块需要重叠

固定边界可能把一句完整规定切到两个块中。重叠可以保留跨边界语义，但过大会增加重复数据和检索噪声。

## 为什么大块信息更多，检索精度反而可能更低

大块可能包含多个主题，但通常只编码成一个向量。当前问题相关的局部语义会被其他内容稀释。大块还可能被Embedding或Reranker截断，并增加Token、延迟和生成噪声。因此大块既可能降低精度，也可能降低效率。

## Embedding与Reranker

```text
Embedding：问题和文档分别编码，速度快，适合大规模召回。
Reranker：同时阅读问题和候选文档，通常更准确，但更慢。
```

## 向量检索与BM25

- 向量检索擅长同义表达和语义相似。
- BM25擅长错误码、编号、姓名和精确术语。
- 两者通过RRF按排名融合，避免直接比较不同分数体系。

## 父子分块

```text
小子块负责“找得准”
父块负责“上下文完整”
```

检索子块后，根据`parent_id`取回完整父块供生成模型使用。

## 多轮查询改写

“取消呢？”无法独立检索，应结合历史改写为“取消会议室预约需要提前多久？”。历史只帮助理解意图，不能代替知识库事实证据。

## 减少无证据回答

- 相关性阈值过滤。
- Reranker或关键词判断。
- 无合格证据时明确拒答。
- Prompt限制只能根据证据回答。
- 生成后检查引用编号和内容支持关系。

## 评估四个维度

1. 检索：Hit@1、Hit@K、MRR、来源和页码命中率。
2. 生成：答案正确性、完整性、忠实性和引用有效性。
3. 拒答：无关问题拒答率和错误拒答率。
4. 性能：平均/P95延迟、Token、API次数、内存和成本。

必须使用固定测试集进行修改前后对比，不能只凭两三个示例判断。
