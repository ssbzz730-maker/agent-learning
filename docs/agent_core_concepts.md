# Agent核心运行机制

## Agent由什么组成

```text
大模型 + 工具 + 控制循环
```

- 模型理解任务、选择工具并生成参数。
- Python程序校验参数、执行工具并保存状态。
- 工具提供外部能力，例如计算、RAG查询或创建工单。

## 一次Tool Calling

```text
用户任务
  ↓
模型返回工具名称、JSON参数和tool_call_id
  ↓
注册表校验并执行真实函数
  ↓
结果以role=tool消息返回模型
  ↓
模型继续调用工具或给出最终答案
```

## Schema与注册表

```text
Tool Schema：模型看到的“菜单”，描述工具和参数。
Tool Registry：程序的“门禁和执行器”，决定是否允许执行。
```

Schema不能替代运行时校验，因为模型可能输出错误参数或未知工具。

## 为什么需要tool_call_id

一轮可能调用多个工具。每条工具结果必须通过`tool_call_id`对应原始调用，否则模型无法判断结果属于哪个请求。

## 控制循环的终止条件

- 没有`tool_calls`且返回了非空`content`：正常完成。
- 达到`max_steps`：失败终止。
- 相同工具和参数重复调用：阻止死循环。
- 无答案也无工具调用：异常终止。

## 工具错误

普通工具异常可以转换成结构化`tool`结果交给模型，使模型修改参数或解释失败。安全违规和不可恢复错误应由控制器直接阻止。

## 状态与人工确认

状态记录消息、步骤、工具结果、运行阶段和待确认操作。查询类只读工具可自动执行；写入、发送、删除等工具必须暂停，并由用户明确确认。

## RAG在Agent中的角色

RAG是Agent可选择的知识工具，不等于Agent本身。Agent可以先调用RAG获取事实，再调用计算器处理数据，最后组织答案。

## 最重要的安全边界

> 模型可以建议做什么，但程序决定允许做什么，用户授权高风险操作。
